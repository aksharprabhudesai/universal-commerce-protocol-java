User Guide

Installation

Add dev.ucomprotocol:ucp-spring-boot-starter:0.3.0 from Maven Central. Requires Spring Boot 4.x and Java 17+ (use version 0.0.1 for Spring Boot 3.x).

Gradle (Groovy)

// build.gradle
dependencies {
    implementation 'dev.ucomprotocol:ucp-spring-boot-starter:0.3.0'
}

Gradle (Kotlin DSL)

// build.gradle.kts
dependencies {
    implementation("dev.ucomprotocol:ucp-spring-boot-starter:0.3.0")
}

Maven

<!-- pom.xml -->
<dependency>
    <groupId>dev.ucomprotocol</groupId>
    <artifactId>ucp-spring-boot-starter</artifactId>
    <version>0.3.0</version>
</dependency>

Example Application & Testing with AI Agents

A stateful, agent-ready storefront is available in the examples/ucp-example directory of the repository. It implements all core UCP capabilities plus configuration-driven AP2 Mandates (catalog.search, catalog.lookup, cart, checkout, payment.ap2_mandate, order, identity_linking) and exposes REST (/ucp/v1), Model Context Protocol Streamable HTTP (/ucp/mcp with 17 tools), and an A2A Agent Card (/.well-known/agent-card.json).

Start the sample storefront (listens on http://localhost:8082):

./gradlew -p examples/ucp-example bootRun

Connect via MCP (Claude Code, Cursor, Claude Desktop, Gemini CLI, Antigravity)

claude mcp add --transport http ucp-store http://localhost:8082/ucp/mcp

Or via mcpServers configuration:

{
  "mcpServers": {
    "ucp-store": {
      "url": "http://localhost:8082/ucp/mcp"
    }
  }
}

Then ask your agent: "Search the UCP store for coffee gear, add a burr grinder and espresso cups to a cart for cust-demo-01, sign an AP2 checkout mandate, and complete checkout."

Connect Any Autonomous HTTP / A2A Agent

Point any HTTP-capable agent at http://localhost:8082/.well-known/ucp or http://localhost:8082/.well-known/agent-card.json so it can dynamically discover capabilities and invoke either /ucp/mcp or /ucp/v1. For a complete step-by-step walkthrough with curl and JUnit examples, read How to Run and Test UCP Java 0.3.0 Locally with Any AI Agent.

Configuration

Configure the library using standard Spring Boot properties in application.properties or application.yml. 

# Default to mock provider for testing
ucp.provider=mock

# Optional: Configuration-Driven AP2 Mandates (dev.ucp.common.payment.ap2_mandate)
ucp.ap2.enabled=true
ucp.ap2.key-id=merchant-ap2-2026
ucp.ap2.algorithm=ES256
ucp.ap2.require-checkout-mandate=true

# Optional: Advertised Transport Endpoints for Discovery (/.well-known/ucp)
# ucp.services.rest-endpoint=https://shop.example.com/ucp/v1
# ucp.services.mcp-endpoint=https://shop.example.com/ucp/mcp
# ucp.services.a2a-endpoint=https://shop.example.com/.well-known/agent-card.json
# ucp.services.embedded-enabled=true

# Optional: Resilience4j Decoration (enabled by default)
# ucp.resilience.enabled=true
# ucp.resilience.instance-name=ucp

Using the Adapters

Inject the CommerceAdapter bean into your services. This bean automatically resolves to the correct implementation based on your configuration.

Searching Products

@Autowired
private CommerceAdapter commerceAdapter;

public List<Product> search(String term) {
    return commerceAdapter.getCatalogAdapter().searchProducts(term);
}

Managing Carts & Checkout

public Cart createCartForUser(String userId) {
    return commerceAdapter.getCartAdapter().createCart(userId);
}

public Checkout startAndCompleteCheckout(Cart cart) {
    Checkout session = commerceAdapter.getCheckoutAdapter().createCheckout(cart);
    return commerceAdapter.getCheckoutAdapter().completeCheckout(session.getId());
}

Discovery Endpoint

One of the key features of UCP Java is the Automatic Discovery Endpoint. This allows clients to query your service and discover which capabilities it supports (e.g., does it support Carts? Orders?).

How to Enable

To enable the /.well-known/ucp endpoint, you simply need to include the Spring Boot Web MVC starter alongside UCP Java. The library detects if you are running a web application and automatically registers the controller.

// build.gradle
dependencies {
    // 1. Add UCP Java
    implementation 'dev.ucomprotocol:ucp-spring-boot-starter:0.3.0'
    
    // 2. Ensure you have the Web MVC Starter (Discovery only works in web apps)
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
}

Advertising Services (optional)

To advertise transport endpoints for the dev.ucp.shopping service, set any of:

ucp.services.rest-endpoint=https://shop.example.com/ucp/v1
ucp.services.mcp-endpoint=https://shop.example.com/ucp/mcp
ucp.services.a2a-endpoint=https://shop.example.com/.well-known/agent-card.json
ucp.services.embedded-enabled=true

Verification

Once your application starts, you can verify the endpoint is active using curl:

curl http://localhost:8080/.well-known/ucp

Response Example:

    "version": "2026-08-25",
    "services": {

          "transport": "rest",
          "endpoint": "https://shop.example.com/ucp/v1",
          "schema": "https://ucp.dev/2026-08-25/services/shopping/rest.openapi.json"
        }
      ]
    },
    "capabilities": {
      "dev.ucp.shopping.catalog.search": [
        {
          "version": "2026-08-25",
          "spec": "https://ucp.dev/2026-08-25/specification/shopping/catalog/search/",
          "schema": "https://ucp.dev/2026-08-25/schemas/shopping/catalog_search.json"
        }
      ],
      "dev.ucp.shopping.catalog.lookup": [ ... ],

This response tells you:

  • Protocol Version: 2026-08-25
  • Services: Transport bindings (REST, MCP, A2A) keyed by service name.
  • Capabilities: A map of supported capabilities and their details.

Changing Providers

To return a different provider in the discovery info, simply change your configuration in application.properties: 

ucp.provider=shopify

The endpoint will use the Shopify adapter to determine capabilities.

Custom Adapters

To implement your own adapter, implement the CommerceAdapter interface and register it as a Spring Bean. The auto-configuration automatically backs off from the mock adapter and wraps your bean with Resilience4j circuit breaker and retry protection.

@Configuration
public class MyCommerceConfig {
    @Bean
    public CommerceAdapter myCustomAdapter() {
        return new MyCustomCommerceAdapter();
    }
}

Defining Capabilities

The Discovery Endpoint automatically detects which capabilities your adapter supports by checking which sub-adapter methods return null (note: getCheckoutAdapter() defaults to null).

For example, if you only support the Catalog, you can implement your adapter like this:

public class ReadOnlyCommerceAdapter implements CommerceAdapter {
    
    @Override
    public CatalogAdapter getCatalogAdapter() {
        return new MyCatalogAdapter(); // Supported
    }

    @Override
    public CartAdapter getCartAdapter() {
        return null; // Not Supported
    }

    @Override
    public OrderAdapter getOrderAdapter() {
        return null; // Not Supported
    }

    @Override
    public CustomerAdapter getCustomerAdapter() {
        return null; // Not Supported
    }
}

When you query the discovery endpoint, it will correctly report:

{
  "ucp": {
    "version": "2026-08-25",
    "services": {},
    "capabilities": {
      "dev.ucp.shopping.catalog.search": [ { "version": "2026-08-25", ... } ],
      "dev.ucp.shopping.catalog.lookup": [ { "version": "2026-08-25", ... } ]
    }
  }
}

Resilience4j Fault Tolerance

In 0.2.0, UcpAutoConfiguration automatically wraps your active CommerceAdapter bean in ResilientCommerceAdapter whenever Resilience4j registries are present on the classpath and ucp.resilience.enabled=true (default). You can tune circuit breaker and retry thresholds using standard Resilience4j Spring Boot properties:

ucp.resilience.enabled=true
ucp.resilience.instance-name=ucp

resilience4j.circuitbreaker.instances.ucp.slidingWindowSize=20
resilience4j.circuitbreaker.instances.ucp.failureRateThreshold=50
resilience4j.retry.instances.ucp.maxAttempts=3
resilience4j.retry.instances.ucp.waitDuration=500ms

AP2 Cryptographic Mandates

Set ucp.ap2.enabled=true to enable the UCP 2026-08-25 AP2 Mandates extension (dev.ucp.common.payment.ap2_mandate) without modifying your CommerceAdapter code. When enabled, Ap2CommerceAdapter signs every Checkout using RFC 8785 JCS + detached JWS (ap2.merchant_authorization), publishes your public EC JWK in /.well-known/ucp keys[], and verifies SD-JWT+kb ap2.checkout_mandate tokens during completeCheckout(checkoutId, ap2):

ucp.ap2.enabled=true
ucp.ap2.key-id=merchant-ap2-2026
ucp.ap2.algorithm=ES256
ucp.ap2.require-checkout-mandate=true

# Optional production PEM/Base64 keys (auto-generates ephemeral EC key if omitted):
# ucp.ap2.auto-generate-ephemeral-key=false
# ucp.ap2.signing-private-key=-----BEGIN PRIVATE KEY-----...
# ucp.ap2.signing-public-key=-----BEGIN PUBLIC KEY-----...
